# 여백 — 컨셉과 주요 기능

**모바일프로그래밍 팀 프로젝트 기준 문서 · 최종**

> AI가 시를 대신 해석하지 않고, 질문을 던져 혼자 읽게 만드는 앱.

이 문서는 기능 단위로 묶은 기준 문서다. 화면·이미지·코드 작업은 모두 이 문서의 기능 ID(F1~F8)와 화면 ID(S01~S12)를 따른다. **기능은 이 문서로 확정한다.**

| 항목 | 내용 |
| --- | --- |
| 팀 | 4인 |
| 산출물 | APK · 사용설명서 · 홍보영상 1분 (15주차) |
| 화면 | 12개 |
| 모델 | OpenRouter (교수님 발급 공용 키) |

## 1. 컨셉

### 한 줄 정의

**질문으로 시를 혼자 읽게 도와주는 앱.** 답을 주지 않고, 사용자가 스스로 해석을 쓰게 한다.

### 풀려는 문제

- 시는 짧아서 시간이 없는 사람에게 오히려 맞는 장르인데, 해석이 어렵다는 이유로 읽히지 않는다.
- 기존 AI 시 해설 서비스는 **해설을 대신 제공한다.** 그 결과 사용자는 시를 읽지 않고 해설을 읽는다.

### 해결 방식

- AI는 답을 주지 않고 **질문만 던진다.** 해석은 사용자가 쓰고 사용자가 저장한다.
- 자기 해석을 저장해야만 전문가 해석, 다른 사람의 대화, 창작 배경이 열린다. **먼저 쓰고, 나중에 본다.**
- 저장 후에는 전문가 해석과 **같은 곳과 다른 곳**을 비교해 볼 수 있다. 정답 확인이 아니라 다른 읽기를 만나는 경험이다.
- 다른 사람이 AI와 어떻게 대화하며 읽었는지 볼 수 있다. 해석이 아니라 **읽는 과정**을 배운다.
- 시를 읽은 날이 쌓이고, 끝까지 읽은 시마다 그 시를 닮은 뱃지가 남는다.

### 하는 것과 하지 않는 것

| 하지 않는 것 | 하는 것 |
| --- | --- |
| 시의 뜻을 대신 설명 | 질문을 던짐 |
| 정답 판정, 채점 | 근거가 시 안에 있는지 확인 |
| 교과서 해설을 먼저 보여줌 | 내 해석을 쓴 뒤에 전문가 해석과 비교 |
| 전문가 해석을 정답으로 제시 | 전문가끼리도 갈리는 읽기를 둘 이상 보여줌 |
| 먼저 힌트를 줌 | 사용자가 요청할 때만 힌트를 줌 |
| 해석의 질로 보상 | 읽은 날과 끝까지 읽은 시로만 보상 |

### 판정 기준

사용자의 해석이 통념과 달라도 부정하지 않는다. 기준은 **교과서와 같은지가 아니라, 시 안에 근거가 있는지**다.

### 쓰지 않는 말

앱의 모든 문구에서 **"정답", "해설", "올바른"**을 쓰지 않는다. 전문가 해석도 여러 읽기 중 하나로 다룬다.

| 홈 문구 | 홈 첫 화면에 "지금까지 N일 시를 읽었어요" | MVP |
| 시 뱃지 | 시마다 그 시의 내용을 닮은 뱃지 하나 (예: 서시 → 별, 진달래꽃 → 꽃, 봄은 고양이로다 → 고양이). 문구 없이 이미지만 | MVP |
| 프로필 | 닉네임 · 누적일수 · 받은 뱃지. 내 것과 남의 것을 같은 화면으로 | MVP |

#### 기준

| 항목 | 언제 올라가나 |
| --- | --- |
| **누적일수** | 그날 시에 들어가면(S04 읽기 진입) **하루 +1**. 같은 날 여러 번 들어가도 1일 |
| **뱃지** | 그 시의 해석을 **최종 저장**하면 획득. 시마다 한 번 |

#### 프로필에 없는 것

팔로워 수, 총 공감 수, 순위, 공개한 대화 목록. 프로필은 **보여주는 선반**이다.

## 4. 전문가 해석과의 대조 규칙

> 관계는 코드가 정한다. AI는 비교 문장만 쓴다.

내 해석과 전문가 해석은 같은 형식으로 저장된다: **근거 행 번호와 핵심 문장.** 저장 후 대조 화면을 열면, 모든 전문가 해석에 대해 코드가 근거 행이 겹치는지를 계산한다.

| 상태 | 화면에 나오는 관계 |
| --- | --- |
| 같은 행을 근거로 삼음 | **같은 곳을 봤어요** |
| 근거 행이 일부만 겹침 | **같은 줄에서 출발했어요** |
| 다른 행을 근거로 삼음 | **이 해석은 N행을 중심으로 읽었어요** |

### 화면에 보이는 순서

1. 내 해석 (가장 위, 가장 무겁게)
2. 전문가 해석 A — 관계 한 줄 + 비교 문장 + 해석 본문
3. 전문가 해석 B — 같은 형식
4. 창작 배경 보기 (버튼, 확장)

### 지키는 것

- 비교 문장은 **공통점부터** 말한다. 같은 점이 없으면 다른 점만 말한다.
- **"전문가는 이 줄도 봤다"처럼 내가 놓친 것을 가리키는 문장은 쓰지 않는다.** 빠진 문항처럼 읽힌다.
- 핵심 문장은 **원문에서 그대로 발췌**한다. 발췌가 원문의 부분 문자열인지 코드로 검사한다.
- 전문가 해석 둘은 서로 입장이 달라야 한다. 전문가끼리도 갈린다는 것이 보여야 어느 하나가 정답이 되지 않는다.
- 라벨은 `전문가 해석 A`, `전문가 해석 B`. 특정 인물 이름을 쓰지 않는다.

### 화면 흐름

```
S01 로그인 ⇄ S02 가입
      │
      ▼
   S03 홈 ─────────┬──────────────┬──────────────┐
      │            │              │              │
      ▼            ▼              ▼              ▼
  S04 읽기     S08 대화 목록   S10 설정 보기   S12 내 프로필
      │            │              │
      ▼            ▼              ▼
  S05 대화     S09 대화 보기   S11 설정 바꾸기
      │            │
      ▼            └─ 닉네임 ──▶ S12 남의 프로필
 S06 정리·저장
      │
      ═══ 저장 ═══▶ S07 대조 ──▶ 창작 배경
      └─ 뱃지 획득
```

하단 탭바는 **시 / 모두의 대화 / 설정** 세 개다. 내 프로필은 홈 상단에서 들어간다.

> **잠금 한 곳.** S06에서 저장해야 S07·S08·S09가 그 시에 대해 열리고 뱃지가 생긴다. 저장하지 않은 시의 전문가 해석과 남의 대화는 어디서도 볼 수 없다.

## 6. 에이전트 구조

대화 한 턴은 고정된 순서로 흐르지 않는다. 모델이 사용자의 답을 읽고 **어떤 툴을 어떤 인자로 부를지 스스로 정하며**, 툴 결과를 다시 읽고 다음 행동을 정한다. 같은 시라도 입력에 따라 툴 조합과 라운드 수가 달라진다.

### 모델 배정 — 요건 (a)의 '다르게'

| 용도 | 모델 성격 | 쓰이는 곳 |
| --- | --- | --- |
| 질문 · 힌트 | 신중한 모델 | S05 대화 — 다음 질문 결정, 힌트 요청 시 관찰 질문 생성 |
| 비교 · 요약 | 빠른 모델 | S05 근거 검증, S07 비교 문장, S09 대화 요약 |

### 툴

| 툴 | 하는 일 | 호출 조건 | 쓰이는 곳 |
| --- | --- | --- | --- |
| `verify_quote` | 인용 구절이 원문에 있는지 대조. 없으면 실패 반환 | 구절을 언급하기 전 항상 | S05 |
| `search_poem_lines` | 시 안에서 낱말을 찾아 행 번호와 반환 | 필요할 때 모델이 결정 | S05 |
| `compare_with_experts` | 4장 규칙으로 전문가 해석 각각과의 관계를 계산해 반환 | **저장 후에만** | S07 |
| `get_poem_context` | 창작 배경 (사실만) | **저장 후에만**. 저장 전 S05에서 부르면 거부 | S07 |

> **툴 권한이 앱 상태에 따라 바뀐다.** 저장 전에는 뒤의 두 툴이 거부된다. "먼저 쓰고 나중에 본다"는 원칙이 프롬프트가 아니라 시스템에서 강제된다.

### 실행 흐름 예시

```
사용자: "이거 연애시 같은데?"
  ├─ verify_quote("사랑해야지")      → found · 6행
  ├─ search_poem_lines("사랑")        → 6행 "모든 죽어가는 것을 사랑해야지"
  └─ "그 구절이면 그렇게 읽을 수 있죠.
      사랑하는 대상이 '모든 죽어가는 것'이라는 점도 같이 보면 어때요?"

사용자: "'별을 그리워하며'라는 구절 때문에"   ← 시에 없는 구절
  ├─ verify_quote("별을 그리워하며")  → not found
  ├─ search_poem_lines("별")          → 5행, 10행 (재탐색)
  └─ "그 표현은 이 시에 없어요. '별'이 나오는 건
      5행과 10행인데, 둘 중 어느 쪽이었을까요?"
```

### verify_quote가 필요한 이유

평가 대응용이 아니라 실제로 필요한 장치다. 무료 티어 모델은 시에 없는 구절을 지어내서 "이 부분을 보면요"라고 말하는 실패를 자주 낸다. 근거를 다루는 앱에서 이건 치명적이다.

인용 전 원문 대조를 강제하면 환각 인용이 앱 밖으로 나가지 못하고, 동시에 **실패 후 재시도**라는 에이전트의 핵심 동작이 자연스럽게 발생한다.

### 모델 출력 제어

LLM은 설명하고 도와주려는 성향이 강해서, "질문만 하라"고 지시해도 턴이 쌓이면 해설로 새어나간다. 프롬프트만으로는 막히지 않으므로 출력 단계에 방어를 둔다.

- **단정형 필터** — "~을 뜻한다", "~을 상징한다", "~입니다" 계열 패턴을 정규식으로 검출하면 재생성
- **질문 종결 검사** — 응답이 물음표로 끝나지 않으면 재생성
- **길이 제한** — 세 문장을 넘으면 재생성. 길어지는 순간 해설이 된다
- **라운드 상한** — 한 턴당 툴 라운드 5회. 초과 시 마지막 라운드를 강제로 응답으로
- **재생성 상한** — 2회. 계속 실패하면 준비된 관찰 질문으로 대체

### 누적일수 계산

```
S04 읽기 진입 시
  오늘 날짜 ≠ 마지막으로 센 날짜  →  누적일수 +1, 마지막으로 센 날짜 = 오늘
  오늘 날짜 = 마지막으로 센 날짜  →  변화 없음
```

날짜는 기기 시간이 아니라 **서버 시간 기준**으로 센다. 기기 시계를 바꿔 일수를 올리는 것을 막는다.

### 무작위 닉네임

- 형식 예: `형용사 + 시에 나오는 명사` (조용한 별, 붉은 꽃잎, 나른한 고양이)
- 새로고침할 때마다 목록에서 새로 조합
- 가입 확정 시 중복 확인. 겹치면 숫자를 붙임

### 전문가 해석 형식

주장마다 근거 행이 붙어 있어야 코드가 관계를 계산할 수 있다.

```json
{
  "poem": "seosi",
  "badge": "badges/seosi.png",
  "readings": [
    {
      "label": "전문가 해석 A",
      "stance": "부끄러움과 다짐으로 읽는 입장",
      "claims": [
        { "lines": [2],       "point": "부끄럼 없기를 바라는 건 도달할 수 없는 기준이다" },
        { "lines": [6, 7, 8], "point": "괴로움을 통과한 뒤에 나온 다짐이다" }
      ]
    },
    {
      "label": "전문가 해석 B",
      "stance": "시대 앞의 무력감으로 읽는 입장",
      "claims": [
        { "lines": [10], "point": "다짐 뒤에도 밤은 그대로 온다" }
      ]
    }
  ]
}
```

### 보안 규칙 요지

- `users/{uid}/readings/**` — 본인만 읽고 쓴다
- 사용자 프로필(닉네임·누적일수·뱃지) — 인증된 사용자 누구나 읽기, 쓰기는 본인만. 누적일수와 뱃지는 **클라이언트가 임의 값으로 쓸 수 없게** 증가·추가만 허용
- 공개 대화 — 쓰기는 본인 문서만. **그 시의 해석을 저장한 사용자만 읽을 수 있도록 규칙에서 막는다.** 클라이언트 분기만으로는 우회 가능
- 멈춤 집계 — 증감만 허용, 임의 값 쓰기 금지

### 오프라인 · 실패 처리

- 시 본문 읽기는 네트워크 없이 동작한다
- 모델 호출 실패 시 미리 준비한 관찰 질문(시별 4개)으로 대체한다. 시연 중 네트워크 사고에 대한 보험이 된다
- 대화 중단(Stop) 버튼을 제공한다
- Firestore 쓰기 실패 시 로컬에 보관하고 다음 실행에서 재시도한다. 저장은 잠금 해제와 뱃지 획득의 분기점이므로 유실되면 안 된다

### API 키 관리

교수님이 발급한 OpenRouter 공용 키를 사용한다.

- 빌드 시 주입하며 **저장소에 커밋하지 않는다** (`--dart-define` 또는 `.gitignore` 처리)
- 앱 화면 어디에도 키를 표시하지 않는다
- 무한 루프로 크레딧이 소진되지 않도록 라운드 상한을 둔다

## 8. 수록 작품

- **기본** — 저작권 만료작. 2013년 보호기간 연장(50년→70년) 시행 이전에 이미 만료된 작품은 연장 대상이 아니므로, 1962년 이전 사망 작가의 작품은 만료로 본다. 윤동주(1945), 김소월(1934), 이장희(1929) 등. 작품별로 개별 확인한다.
- **추가** — 팀이 주기적으로 시를 추가한다. 시 하나를 추가할 때마다 **본문 JSON + 전문가 해석 둘 + 뱃지 이미지 하나**가 한 세트다.
- **주의** — 번역시와 특정 판본의 편집 저작권은 원작과 별개다. 원문 표기는 만료된 원전 기준으로 정리한다.
- **전문가 해석** — 여러 평론을 읽고 팀이 이해한 방식으로 다시 쓴다. 원문 문장을 옮기지 않으며, 특정 인물 이름 대신 "전문가 해석 A/B"로 표기한다.
- **현대시** — 서면으로 허락받은 작품만 수록한다. 허락 기록을 보관한다.
- **수록하지 않는 것** — 저작권이 살아 있는 유명 현대시. APK에 본문이 포함되면 배포에 해당할 수 있어 제외한다.
