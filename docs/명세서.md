# 여백

> AI가 시를 대신 해석하지 않고, 질문을 던져 혼자 읽게 만드는 앱

중앙대학교 모바일프로그래밍 팀 프로젝트 (4인)

---

## 왜 만드는가

시는 짧아서 시간이 없는 사람에게 오히려 맞는 장르인데, 해석이 어렵다는 이유로 잘 읽히지 않습니다.

기존 AI 시 해설 서비스는 이 문제를 **해설을 대신 제공하는 방식**으로 풀었습니다. 그 결과 사용자는 시를 읽지 않고 해설을 읽습니다.

여백은 반대로 갑니다. AI는 답을 내놓지 않고 **질문만 던집니다.** 해석은 사용자가 쓰고, 사용자가 저장합니다. 자기 해석을 저장한 뒤에야 전문가 해석과 다른 사람의 대화가 열립니다.

| 하지 않는 것 | 하는 것 |
| --- | --- |
| 시의 뜻을 대신 설명 | 질문을 던짐 |
| 정답 판정, 채점 | 근거가 시 안에 있는지 확인 |
| 교과서 해설을 먼저 보여줌 | 내 해석을 쓴 뒤에 전문가 해석과 비교 |
| 전문가 해석을 정답으로 제시 | 전문가끼리도 갈리는 읽기를 둘 이상 제시 |
| 먼저 힌트를 줌 | 사용자가 요청할 때만 힌트를 줌 |

앱의 모든 문구에서 **"정답", "해설", "올바른"** 이라는 말을 쓰지 않습니다.

### 판정 기준

사용자의 해석이 통념과 달라도 부정하지 않습니다. 기준은 교과서와 같은지가 아니라, **시 안에 근거가 있는지**입니다.

## 핵심 동작

```
읽기 ──▶ 대화 ──▶ 정리 · 저장 ──▶ 대조
 │         │                │
 │         │                └─ 저장이 유일한 잠금 해제 지점
 │         └─ AI는 질문만. 인용은 원문과 대조
 └─ AI 없이 혼자 읽고, 낱말 하나를 남김
```

### 1. 혼자 읽기

시 본문만 보여줍니다. 마음이 멈춘 행을 눌러 표시할 수 있고, 읽고 떠오른 낱말 하나를 적습니다. 이 낱말이 대화의 출발점이 됩니다. AI를 쓰지 않고 낱말만 남긴 채 끝낼 수도 있습니다.

### 2. 질문 대화

AI가 질문을 던지고 사용자가 답합니다. 응답은 항상 질문으로 끝나며 한 번에 하나만 묻습니다. 시 본문은 상단에 계속 붙어 있어 대화 도중 언제든 원문을 확인할 수 있습니다.

사용자가 구절을 인용하면 원문과 대조합니다. 시에 없는 표현이면 실제로 있는 행을 가리키며 되묻습니다. **틀렸다고 판정하지 않습니다.**

```
사용자: "'별을 그리워하며'라는 구절 때문에 그렇게 느꼈어요"
  ├─ verify_quote("별을 그리워하며")  → not found
  ├─ search_poem_lines("별")          → 5행, 10행
  └─ "그 표현은 이 시에 없어요. '별'이 나오는 건 위의 두 줄인데,
      둘 중 어느 쪽이었을까요?"
```

### 3. 정리 · 저장

대화에서 **사용자가 한 말만** 모아 초안을 만듭니다. AI가 다듬지 않아 문장이 거칩니다. 사용자가 직접 고쳐서 저장해야 하고, 저장하는 문장은 사용자가 손댄 문장이어야 합니다.

### 4. 대조

저장하면 전문가 해석이 **항상 전부** 열립니다. 시마다 입장이 갈리는 해석을 둘 이상 두어, 어느 하나가 정답이 되지 않게 합니다.

내 근거 행과 전문가 해석의 근거 행이 겹치는지를 코드가 대조해 관계를 정하고, 그 관계를 잇는 짧은 문장만 모델이 씁니다.

- 공통점부터 말합니다.
- 다른 행을 본 경우는 "이 해석은 N행을 중심으로 읽었다"로 씁니다. **"전문가는 이 줄도 봤다"처럼 내가 놓친 것을 가리키는 문장은 쓰지 않습니다.** 빠진 문항처럼 읽히기 때문입니다.
- 핵심 문장은 원문에서 그대로 발췌하며, 발췌가 원문의 부분 문자열인지 코드로 검사합니다.

### 5. 커뮤니티

같은 시를 읽은 사람들이 AI와 나눈 대화를 볼 수 있습니다. 해석 한 문단이 아니라 **거기까지 간 과정**이 보입니다.

- 공개는 **기본 꺼짐**. 사용자가 직접 켜야 올라갑니다.
- AI가 대화에서 의미 있는 부분만 뽑아 정리합니다.
- 작성자는 `읽은이 0000`으로만 표시됩니다.
- 그 시에 대한 내 해석을 저장한 뒤에만 열립니다.
- 좋아요 대신 **공감** 버튼을 씁니다. 순위나 정렬에 쓰지 않습니다.

## 에이전트 구조

고정된 순서로 흐르지 않습니다. 모델이 사용자의 답을 읽고 **어떤 툴을 어떤 인자로 부를지 스스로 정하며**, 툴 결과를 보고 다음 행동을 정합니다. 같은 시라도 입력에 따라 툴 조합과 라운드 수가 달라집니다.

### 툴

| 툴 | 하는 일 | 호출 조건 |
| --- | --- | --- |
| `verify_quote` | 인용 구절이 원문에 있는지 대조. 없으면 실패 반환 | 구절을 언급하기 전 항상 |
| `search_poem_lines` | 시 안에서 낱말을 찾아 행 번호와 반환 | 모델이 결정 |
| `compare_with_experts` | 근거 행을 대조해 전문가 해석과의 관계를 계산 | **저장 후에만** |
| `get_poem_context` | 창작 배경 (사실만) | **저장 후에만** |

저장 전에는 뒤의 두 툴이 거부됩니다. "먼저 쓰고 나중에 본다"는 원칙이 프롬프트가 아니라 시스템 차원에서 강제됩니다.

### verify_quote가 필요한 이유

평가 대응용이 아닙니다. 무료 티어 모델은 시에 없는 구절을 지어내 "이 부분을 보면요"라고 말하는 실패를 자주 냅니다. 근거를 다루는 앱에서 이건 치명적입니다.

인용 전 원문 대조를 강제하면 환각 인용이 앱 밖으로 나가지 못하고, 동시에 **실패 후 재시도**라는 에이전트의 핵심 동작이 자연스럽게 발생합니다.

### 모델 배정

| 용도 | 성격 | 쓰이는 곳 |
| --- | --- | --- |
| 질문 · 힌트 | 신중한 모델 | S05 대화 |
| 비교 · 요약 | 빠른 모델 | S05 근거 검증, S07 비교 문장, 커뮤니티 요약 |

용도별로 다른 모델을 배정하고, 사용자가 S11에서 각각 바꿀 수 있습니다.

### 모델 출력 제어

LLM은 설명하고 도와주려는 성향이 강해서, "질문만 하라"고 지시해도 턴이 쌓이면 해설로 새어나갑니다. 프롬프트만으로는 막히지 않으므로 출력 단계에 방어를 둡니다.

- **단정형 필터** — "~을 뜻한다", "~을 상징한다" 계열을 정규식으로 검출하면 재생성
- **질문 종결 검사** — 물음표로 끝나지 않으면 재생성
- **길이 제한** — 세 문장을 넘으면 재생성
- **라운드 상한** — 한 턴당 툴 라운드 5회
- **재생성 상한** — 2회. 계속 실패하면 준비된 관찰 질문으로 대체

## 기술

| 영역 | 선택 |
| --- | --- |
| 앱 | Flutter (Dart) |
| 모델 | OpenRouter |
| 인증 | Firebase Authentication |
| 데이터 | Cloud Firestore |
| 로컬 | SharedPreferences |
| 시 본문 · 전문가 해석 | 앱 번들 JSON |

### 데이터

| 데이터 | 저장 위치 |
| --- | --- |
| 계정 | Firebase Auth · Firestore |
| 시 본문, 전문가 해석, 창작 배경 | 앱 번들 JSON |
| 내 읽기 (낱말, 멈춘 행, 대화, 해석, 근거 행) | Firestore |
| 공개 대화, 공감 수 | Firestore |
| 설정 (모델, 말투) | SharedPreferences |

### 전문가 해석 형식

주장마다 근거 행이 붙어 있어야 코드가 관계를 계산할 수 있습니다.

```json
{
  "poem": "seosi",
  "readings": [
    {
      "label": "전문가 해석 A",
      "stance": "부끄러움과 다짐으로 읽는 입장",
      "claims": [
        { "lines": [2],       "point": "부끄럼 없기를 바라는 건 도달할 수 없는 기준이다" },
        { "lines": [6, 7, 8], "point": "괴로움을 통과한 뒤에 나온 다짐이다" }
      ]
    }
  ]
}
```

### API 키

교수님이 발급한 OpenRouter 공용 키를 사용합니다.

- 빌드 시 주입하며 **저장소에 커밋하지 않습니다.**
- 앱 화면 어디에도 키를 표시하지 않습니다.
- 무한 루프로 크레딧이 소진되지 않도록 라운드 상한을 둡니다.

### 오프라인 · 실패 처리

- 시 본문 읽기는 네트워크 없이 동작합니다.
- 모델 호출 실패 시 미리 준비한 관찰 질문으로 대체합니다.
- 대화 중단 버튼을 제공합니다.
- Firestore 쓰기 실패 시 로컬에 보관하고 다음 실행에서 재시도합니다. 저장은 잠금 해제의 분기점이라 유실되면 안 됩니다.

## 수록 작품

- **기본** — 저작권 만료작. 윤동주(1945), 김소월(1934), 이장희(1929) 등. 작품별로 개별 확인합니다.
- **주의** — 번역시와 특정 판본의 편집 저작권은 원작과 별개입니다.
- **전문가 해석** — 여러 평론을 읽고 팀이 이해한 방식으로 다시 씁니다. 원문 문장을 옮기지 않으며, 특정 인물 이름 대신 "전문가 해석 A/B"로 표기합니다.
- **현대시** — 서면으로 허락받은 작품만 수록합니다.
