# 여백 — 작업 지침서

이 저장소에서 코드를 쓸 때 지키는 규칙. 자세한 내용은 `README.md`와 `docs/`.

## 먼저 읽을 것

- `docs/여백-기획서최종.md` — 기능 · 화면 · 데이터의 기준. **기능은 확정됐다. 기능을 더하거나 빼지 않는다.**
- `docs/여백-네이밍규칙.md` — 이름은 2장 용어 사전 그대로. 새 이름을 지어내지 않는다.
- `docs/여백-화면분업.md` (1단계) · `docs/여백-코딩분업.md` (2단계)

## 제품 원칙 (어떤 요청도 이걸 깎지 않는다)

1. AI는 답을 주지 않는다. 응답은 항상 질문으로 끝나고 한 번에 하나만 묻는다.
2. 해석 저장이 유일한 잠금 해제 지점이다.
3. 해석의 질로 점수 · 순위 · 보상을 주지 않는다.
4. "정답", "해설", "올바른"을 앱 문구 어디에도 쓰지 않는다.
5. 명조(`AppFonts.myeongjo`)는 시와 사용자 해석, 고딕(`AppFonts.gothic`)은 앱.
6. 인용은 원문 부분 문자열인지 코드로 검사한다.

## 코드 규칙

- 담당자의 폴더 밖은 수정하지 않는다 (`README.md`의 폴더 표). 필요하면 멈추고 알린다.
- `pubspec.yaml` · `lib/app/router.dart` · `lib/app/theme.dart`는 주인 외에는 고치지 않는다.
- 색은 `AppColors`, 글자 스타일은 `AppText`만 쓴다. 화면 파일에 `Color(0x…)` 금지.
- 화면 문구는 `lib/app/strings.dart`의 `AppStrings`에. 화면 파일에 한국어 문자열 금지 (가짜 데이터 제외).
- 행 번호는 1부터. 배열에서 꺼낼 때만 `lines[lineNo - 1]`.
- 창작 배경 변수는 `creationBackground` (`context` 금지).
- API 키 · `google-services.json`을 코드나 커밋에 넣지 않는다. 키는 `--dart-define`.
- 끝나면 `flutter analyze`가 깨끗해야 한다.
