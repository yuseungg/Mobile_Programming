## 1. 판단 기준

**커밋 조상 관계로 판단하면 안 된다.** 우리는 squash merge를 쓴다
(`docs/여백-코딩분업.md` 4장). squash는 새 커밋 하나를 만들기 때문에,
머지가 끝난 브랜치의 끝 커밋은 `develop` 의 조상이 **아니다**.

```
$ git merge-base --is-ancestor origin/feat/chat-agent origin/develop
→ 실패. 그런데 #5는 머지됐고 그 코드는 develop에 있다.
```

그래서 기준은 조상 관계가 아니라 **PR 상태**다.

| PR 상태 | 판단 |
| --- | --- |
| MERGED | 코드가 develop에 있다 → 지운다 |
| CLOSED | 넣지 않기로 한 작업이다 → 지운다 |
| OPEN | 남긴다 |
| PR 없음 | 브랜치의 내용이 develop에 있는지 **파일로 직접 확인**한 뒤 판단 |

확인에 쓴 명령:

```bash
gh pr list --state all --limit 100 --json number,headRefName,state
```

## 4. 삭제 명령

자기 브랜치는 각자 지운다. 남의 브랜치는 지우지 않는다.

```bash
git fetch --prune
```

```bash
git push origin --delete <브랜치> <브랜치> ...
```

지운 뒤 다른 사람 쪽에서 사라진 원격 추적 브랜치를 정리하려면:

```bash
git remote prune origin
```

로컬 브랜치는 따로 남으므로 필요하면 `git branch -d <브랜치>` 로 지운다
(머지 안 된 것으로 보여 거부하면 `-D`. squash 때문에 그렇게 보이는 것이다).

## 5. 다시 쌓이지 않게

저장소 설정에서 **Automatically delete head branches** 를 켠다.
`Settings → General → Pull Requests` 에 있는 체크 상자 하나다.
켜 두면 PR이 머지될 때 머리 브랜치가 자동으로 지워진다.
저장소 소유자만 켤 수 있다.

따로 워크플로를 만들지 않는다. GitHub에 이미 있는 기능이다.

지워진 브랜치의 커밋은 PR 페이지에 그대로 남고, 되살리려면 PR 화면의
**Restore branch** 를 누르면 된다. 되돌릴 수 없는 작업이 아니다.

## 6. 한글 경로를 확인할 때

git은 기본 설정에서 ASCII 밖의 경로를 이스케이프해서 출력한다.

```
$ git ls-tree -r --name-only origin/develop | grep 대조표
(아무것도 안 나온다)

$ git -c core.quotepath=false ls-tree -r --name-only origin/develop | grep 대조표
docs/여백-이름대조표.md
```

이 문서를 쓰면서 실제로 한 번 틀렸다. `docs/name-mapping` 을 "develop에
없으니 남겨야 한다"고 판단했는데, `grep` 이 `"docs/\354\227\254..."` 를
못 찾았을 뿐이었다. 우리 저장소는 문서 이름이 전부 한글이므로
경로를 찾을 때는 `-c core.quotepath=false` 를 붙인다.
