# 여백 — 1단계 화면 분업

> 이번 단계는 **화면과 화면 이동만** 만든다. 기능(Firebase, 모델 호출, 저장)은 화면이 다 끝난 뒤 2단계에서 붙인다.
> 함께 볼 문서: `여백-기획서최종.md` · `여백-코딩분업.md` · `여백-네이밍규칙.md`

---

## 1. 분배

나중에 기능을 붙일 사람이 그 화면을 그대로 맡는다. 2단계에서 남이 만든 화면을 이어받아 뜯어고칠 일이 없게 하기 위해서다.

| | 화면 | 공용으로 만드는 것 |
| --- | --- | --- |
| **A** | S05 대화 | **테마**, 공용 버튼 · 입력칸 · 카드, 말풍선, 메시지 입력창 |
| **B** | S03 홈 · S04 읽기 · S06 정리·저장 | **시 본문 위젯 (`PoemView`)** |
| **C** | S01 로그인 · S02 가입 · S10 설정 보기 · S11 설정 바꾸기 | **라우터**, 하단 탭바 |
| **D** | S07 대조 · S08 대화 목록 · S09 대화 보기 · S12 프로필 | **가짜 데이터** |

### 작업량

| | 화면 | 공용 | 무게 |
| --- | --- | --- | --- |
| A | 무거움 1 | 테마 + 공용 위젯 여러 개 | ●●●○ + 에이전트 PoC |
| B | 보통 3 | 시 본문 위젯 (가장 까다로움) | ●●●● |
| C | 가벼움 4 | 라우터 · 탭바 | ●●●○ |
| D | 보통 4 | 가짜 데이터 | ●●●● |

A는 화면이 하나라 가볍다. 테마와 공용 위젯을 끝낸 뒤 남는 시간에 **에이전트 PoC**(서시 한 편, `verify_quote`, 없는 구절을 넣었을 때 재탐색되는지)를 시작한다. 이 프로젝트에서 가장 위험한 부분이라 미리 확인해둬야 한다.

## 2. 첫날 — 공용부터

아래 넷이 먼저 `develop`에 올라가야 나머지가 시작할 수 있다. **각자 PR 하나씩, 첫날 안에.**

| 누가 | 무엇을 | 파일 |
| --- | --- | --- |
| **C** | 12개 화면을 **제목만 있는 빈 화면**으로 만들고, 3장 표대로 이동과 탭바 연결 | `app/router.dart`, `features/*/…_screen.dart` (빈 껍데기) |
| **A** | 기획서 부록 B 색 · 글꼴로 테마, 공용 버튼 · 입력칸 · 카드 | `app/theme.dart`, `shared/widgets/` |
| **B** | 시 본문 위젯 | `shared/widgets/poem_view.dart` |
| **D** | 가짜 데이터 파일 하나 | `data/fakes/fake_data.dart` |

C가 빈 화면을 올린 다음부터는 **각자 자기 화면 파일 안만** 채운다. 이러면 `router.dart`에서 충돌이 나지 않는다.

### 시 본문 위젯이 해야 할 것

S04 · S05 · S07에서 같이 쓴다. B가 만들고 A · D가 가져다 쓴다.

| 표시 | 쓰이는 곳 |
| --- | --- |
| 시 전체, 넉넉한 줄간격 (명조) | S04 |
| 행 탭 시 와인색 배경 + 오른쪽에 "7명" | S04 |
| 확인된 근거 행에 **초록 실선** | S05 · S07 |
| 가리키는 중인 행에 **회색 점선** | S05 |
| 몇 행만 작게, 위에 고정 (스크롤 가능) | S05 |

B의 위젯이 올라오기 전에는 S05(A)와 S07(D)에서 **임시로 글자만 띄워두고**, 올라오면 바꿔 끼운다.

### 가짜 데이터에 들어갈 것

| 항목 | 내용 |
| --- | --- |
| 시 | 서시 · 진달래꽃 · 봄은 고양이로다 (본문 전체) |
| 전문가 해석 | 서시 A · B 두 개 (기획서 7장 형식) |
| 내 읽기 | 서시 — 첫 낱말 "부끄러움", 대화 3~4턴, 해석 한 문단, 근거 행 6행 |
| 공개 대화 | 서시 3개 (닉네임 · 첫 낱말 · 요약 · 해석 · 공감 수) |
| 사용자 | 닉네임 "조용한 별", 누적일수 12, 뱃지 1개 (서시) |
| 설정 | 질문 모델 · 비교 모델 · 말투 기본값 |

이름은 `여백-네이밍규칙.md` 2장 용어 사전대로 쓴다. 2단계에서 그대로 진짜 데이터로 바꿀 수 있게 하기 위해서다.

## 4. 화면별로 들어갈 것

목업 이미지를 기준으로 하되, 아래와 다른 부분은 **이 문서와 기획서가 우선**이다.

| 화면 | 담당 | 들어갈 것 | 참고 이미지 |
| --- | --- | --- | --- |
| S01 로그인 | C | 앱 이름 · 부제, 이메일 · 비밀번호, 로그인, 구글로 시작하기, 가입하기 링크 | 입력 필드 주석본 |
| S02 가입 | C | 이메일 · 비밀번호 · 비밀번호 확인, **무작위 닉네임 + 새로고침 버튼**, 가입하기 | 주석본 (닉네임 줄은 기획서 기준으로 변경) |
| S03 홈 | B | **"지금까지 N일 시를 읽었어요"**, 오늘의 시 카드, 내가 읽은 시 목록, 상단 프로필 진입, 탭바 | 홈 목업 (누적일수 줄 추가) |
| S04 읽기 | B | 시 본문 (행 탭), 첫 낱말 입력, 버튼 둘 | 주석본 |
| S05 대화 | A | 상단 고정 시, 말풍선, 입력창, 힌트 · 정리하기 버튼 | 주석본 |
| S06 정리·저장 | B | 해석 편집칸 (글자 수), 근거 구절, 공개 토글, 저장하기 | 주석본 |
| S07 대조 | D | 내 해석, **전문가 해석 A · B** (관계 한 줄 + 비교 문장 + 본문), 창작 배경 · 다른 사람의 대화 버튼 | ⚠ 옛 목업은 구조가 다름 — 기획서 4장 기준 |
| S08 대화 목록 | D | 시 선택 칩 (저장 안 한 시는 자물쇠), 대화 카드 (닉네임 · 첫 낱말 · 요약) | 목록 목업 |
| S09 대화 보기 | D | 닉네임 (누르면 프로필), 첫 낱말, 대화 요약, 해석, 공감 | 상세 목업 (작성자 표시를 닉네임으로) |
| S10 설정 보기 | C | 모델 배정 2개, 말투, 사용량, 설정 바꾸기 | 옛 목업 (보조바퀴 영역 빼기) |
| S11 설정 바꾸기 | C | 질문 모델 · 비교 모델 선택, 말투, 기록 지우기, 저장 | 주석본 |
| S12 프로필 | D | 닉네임, 누적일수, 받은 뱃지 | ⚠ 목업 없음 — 기획서 F8 기준 |

### 이 단계에서 하지 않는 것

- Firebase 연결, 로그인 검증, 모델 호출
- 입력 제한 (글자 수 · 비밀번호 차단 등) — 글자 수 **표시**만 해두고 막는 건 2단계
- 저장 전 잠금 — 이 단계에서는 **늘 열린 상태**로 둔다
- 버튼은 다음 화면으로 넘어가기만. 기능이 없는 버튼은 눌러도 아무 일 없게

## 5. 완료 기준

아래가 다 되면 1단계 끝. 2단계(기능)로 넘어간다.

- [ ] 12개 화면이 전부 열린다
- [ ] 3장 표의 이동이 전부 작동하고, 뒤로 가기가 된다
- [ ] 하단 탭바가 S03 · S08 · S10에서만 보이고 전환된다
- [ ] 가짜 데이터가 화면에 보인다 (빈 화면 없음)
- [ ] 색 · 글꼴은 전부 공용 테마에서 온다. 화면 파일 안에 색 코드를 직접 쓰지 않았다
- [ ] 화면 문구는 `strings.dart`에 모여 있다
- [ ] `develop`에서 앱이 빌드되고 처음부터 끝까지 눌러볼 수 있다

마지막 확인은 **네 명이 같이** 한다. S01부터 시작해 로그인 → 읽기 → 대화 → 저장 → 대조 → 커뮤니티 → 프로필 → 설정까지 한 번에 눌러본다.
